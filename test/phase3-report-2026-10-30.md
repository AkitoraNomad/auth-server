- 客户端：编辑名称、多回调、Scope、grant_types、Token 类型；启用/停用；机密客户端 secret 重置并单次展示。
- 四个列表：分页、名称/邮箱/ID 查询、启停状态筛选；越界页码自动回退，空数组结构稳定。

- 管理客户端只读保护；public/confidential 类型创建后固定；保护最后一名可用管理员，停用管理员不计入可用人数。

## 安全行为

用户/客户端安全版本和资料、状态、凭据在同一 PostgreSQL 事务中更新。授权码、授权族和 SSO 绑定相应版本：

- 用户邮箱、状态或密码变更使原用户授权码、Access/Refresh Token 和 SSO 失效；仅改显示名称不下线。
- 客户端配置、状态或 secret 变更使该客户端的原授权码、用户 Token 和 client_credentials Token 失效；不结束用户在其他可用客户端使用的全局 SSO。
- 重新启用不会恢复旧授权。停用客户端也不能通过 Basic 认证查询 Introspection/UserInfo。
- 凭据验证绑定读取 provider 时的用户版本；验证期间若账号版本变化，会拒绝此次登录，避免将新版本附着到旧密码验证结果。
- 客户端配置 PUT 不修改启停状态，防止旧编辑表单意外覆盖另一位管理员刚设置的停用状态。
- 管理客户端启动 seed 在安全配置改变时递增版本；相同配置保持幂等。原有 PKCE、刷新重放、CSRF、近期认证和撤销保护保留。

按用户要求删除全部增量迁移脚本、迁移专用测试及执行说明，只维护最新基础表结构。经授权直接调整 `10.0.0.148:5432/postgres` 的 `auth` schema，未执行含 `DROP TABLE` 的初始化脚本：

- 用户与客户端表各增加 `is_disabled BOOLEAN NOT NULL DEFAULT FALSE` 和 `security_version BIGINT NOT NULL DEFAULT 0`。

## 2026-10-31 客户端页面空值修复

手工测试发现客户端页因对 `null` 调用 `join` 而白屏：数据库允许 `scopes` 为 SQL NULL，原后端将其序列化为 JSON null，前端却按数组使用。此前回归的客户端 scopes 都非空，未覆盖这一边界。

修复后，`TextArray` 在 JSON 输出时将 nil 转为 `[]`；前端在客户端 API 读取处将 `scopes`、`redirect_uris`、`grant_types` 的 null 转为空数组，兼容仍运行旧版本的后端。数据库数据及原有授权策略保持原值。

先通过新增单测复现 nil 输出 null 的失败，再验证修复。真实 PostgreSQL 集成新增 SQL NULL scopes 和空回调/授权类型的客户端，断言接口返回空数组。浏览器验证该客户端列表与编辑，并模拟旧后端三个字段均为 null，实际点击桌面与手机布局的编辑按钮，确认空 Scope、未勾选 grant 和 domain 回退正确。完整复测结果见上表。
